# ICM Workspace Layout & Contracts

Universal AI SDLC organizes repository governance using **Interpretable Context Methodology (ICM)**:

1. **Factory vs. Product Separation:**
   - `_shared/` holds stable governance docs, observability standards, and project invariants across runs.
   - `_templates/` holds reusable templates copied when starting a new `REQ`, `ADR`, `THR`, `SPEC`, or `POSTMORTEM`.
   - `01_requirements/` .. `07_release_maintenance/` hold run/feature deliverables inside `output/` so humans and auditors can inspect pipeline state directly on disk.
2. **Explicit Stage Contracts (`CONTEXT.md`):**
   Every stage directory contains a `CONTEXT.md` declaring:
   - `Inputs` (working outputs from prior stage + stable `_shared/` docs)
   - `Do NOT load` (prevents context-stuffing across unrelated stages)
   - `Process` (step-by-step gate transformation)
   - `Outputs` (where artifacts land under `output/`)
   - `Human check` (concrete review action before advancing)
3. **Filesystem as State Machine:**
   Pipeline progress is derived strictly by inspecting `.sdlc/01..07/*/output/` and `.sdlc/06_verification/output/proof-status.json`.
